This is a review-only Android job recipe. It does not dispatch CI, create a release, upload an asset or contact the log backend. The parent plan remains unfrozen until root accepts the complete product/test source union.

The overall workflow materializes `source-product` and `source-test` using the adjacent `materialize.py`, yielding one source proof per layer. The runner then builds the clean product as the normal `space.nuvio.nativelegacy` debug APK and the isolated test layer as the account-compatible `space.nuvio.nativelegacy.touch`, versionCode20018, versionName2.0.18-test-logs8, label Nuvio TV/Mobile Test. Both use the persistent certificate required by the current test installation. Only the test layer enables private diagnostics; Download itself is public product code.

The private properties file and debug keystore stay under runner-temp, outside uploaded artifact paths. A blank report URL uses the documented original service; an explicit nonempty override is preserved. The original Send/View logic is not intercepted by these helpers. Only an exact, hash-recorded CI debug signer insertion touches tracked product source, and it is restored after successful verification. The test layer already pins its compatible identity/signing hook; those are verified and its tracked source remains unchanged.

Each layer uses production `tools/android/deps.sh` and `tools/android.sh` for a full Kotlin/ARM32/ARM64 build. Verification reads the actual APK DEX, compiled Kotlin classes and native compile databases; checks all NvPlayer JNI lookups and legacy overloads, the public Download Activity/helper bridge, test opt-in, package/version/label, persistent certificate, FileProvider authority and restricted updater path, required native libraries/assets and 16KB page packaging. No emulator/physical-device execution is claimed. Generated configurations and compile databases are inspected locally, not copied into artifact output.

`job-fragment.json` is a named-step fragment for the parent workflow. It must be included directly or generated by named job/step identity, never by fixed YAML step indices. Cache restore precedes both layers, and cache save uses the exact primary keys only after outputs exist; invalid source/proof/identity checks fail before compilation. Final verification must be rerun after every product/test pin change.

Transform receipts are evidence, never mutation permission: verification independently allows only the exact product Gradle debug-signer insertion, requires no test-layer edits, binds the source-proof hash, and in CI requires the current GITHUB_SHA. Forged receipt-listed C/build-script edits are rejected by the offline preflight.

Both cache restore actions keep the Logs8 primary key and first fallback, then try the previously proven Android-touch cache family. Production deps.sh still runs for both layers and validates its own recipe/NDK stamps. Only exact hit, matched key and restore outcome are saved in a safe receipt and job summary; private build values are never captured.
